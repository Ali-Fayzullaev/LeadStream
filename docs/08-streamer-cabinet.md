# 08 · Личный кабинет стримера

URL: `/streamer`
Доступ: только пользователь с `role='streamer'` и `status='active'`.

## 🎯 Цели кабинета

1. Дать стримеру **его ссылку** в один клик (copy / QR).
2. Показать **его** статистику — мотивирует.
3. Показать **его** клиентов и заказы.
4. Показать ожидаемые **выплаты**.

## 🧭 Навигация

```
┌────────────────────────────────────┐
│ LeadStream | 🌙 | 🔔 | 👤 Alex    │
├────────────────────────────────────┤
│  Дашборд  Заказы  Профиль  Выйти   │
├────────────────────────────────────┤
│                                    │
│            Контент                 │
│                                    │
└────────────────────────────────────┘
```

## 📄 Страницы

### `/streamer` — Дашборд

#### 1. Карточка реф-ссылки (выделенная, сверху)
- Полный URL: `https://yourshop.com/?ref=alex_2024`
- Кнопка **«Скопировать»** (копирует в буфер, toast).
- Кнопка **«Скачать QR»** (qrcode.react → png).
- Кнопка **«Поделиться»** (Web Share API на мобильном).

#### 2. Карточки KPI (4 штуки)
| Карточка | Подсчёт |
|---|---|
| Заказов сегодня | count(orders where created_at >= today and streamer_id = me) |
| Заказов за месяц | count(orders where created_at >= now()-30d and streamer_id = me) |
| Выручка за месяц | sum(amount) той же выборки |
| Заработано за месяц | выручка × commission_percent / 100 |

Прирост к прошлому периоду (стрелка ↑/↓ %).

#### 3. График по дням
- Recharts area-chart, последние 30 дней.
- Toggle: «Заказы» / «Выручка» / «Заработок».

#### 4. Топ-3 моих лучших дня
Сортировка дней по выручке.

### `/streamer/orders` — Список заказов

Таблица:
| Столбец | Что |
|---|---|
| Дата | `dd MMM HH:mm` |
| Имя клиента | полное |
| Телефон | **частично скрыт** (`+7 999 ***-**-67`) — антифрод |
| Товар | название |
| Кол-во | число |
| Сумма | currency |
| Мой % | `amount × commission / 100` |
| Статус | бейдж (new / confirmed / shipped / completed / cancelled) |

Фильтры сверху:
- Период (today / week / month / all / custom range).
- Статус (мульти-чек).
- Поиск по имени.

Действия:
- Экспорт **только своих** заказов в CSV/Excel.

### `/streamer/profile` — Профиль

Поля редактируемые:
- Аватар (Supabase Storage, public bucket `avatars`).
- ФИО.
- @TikTok ник.
- Телефон.
- (Опционально) Telegram username для уведомлений.
- Смена пароля.

Поля только для чтения:
- Email (смена через отдельный flow с подтверждением).
- ref_code (изменение — только запросом админу, чтобы не ломать историю).
- Статус аккаунта.
- Дата регистрации.

Переключатель: **«Получать уведомления о новых заказах в Telegram»** (вкл/выкл).

## ⏳ Состояние «На модерации»

Если `streamers.status = 'pending'`:
- Все маршруты `/streamer/*` редиректят на `/streamer/pending`.
- Страница говорит: «Спасибо за регистрацию! Админ рассмотрит заявку в течение 24 часов».
- Кнопка «Связаться в Telegram».

## 🚫 Состояние «Заблокирован»
Если `status='blocked'` — страница `/streamer/blocked` с причиной (поле `notes` админа).

## 🔐 Безопасность данных

- RLS на `orders`: стример видит **только** заказы, где `streamer_id = (select id from streamers where user_id = auth.uid())`.
- Телефон клиента маскируется на клиенте (логика в utils, но честно — RLS не маскирует, и стример теоретически может вытащить полный через DevTools; для строгой приватности — добавить view с маскировкой, см. [13-security.md](./13-security.md)).
- Никаких `service_role`-операций из кабинета стримера.

## 🎨 Дизайн

- Sidebar или top-nav (выбираем top-nav для простоты на мобильном).
- Карточки KPI в стиле Stripe / Linear: лёгкая тень, тонкая граница, цветной акцент в углу (radial blur).
- Анимация чисел (count-up) при загрузке.
- Loading skeletons вместо spinner-а — выглядит дороже.
