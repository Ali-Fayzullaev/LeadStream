# 01 · Роли и пользовательские сценарии

## 👥 Три роли

### 1. 👤 Visitor (Клиент / посетитель)
- Не регистрируется.
- Заходит на лендинг (часто по ссылке стримера в TikTok bio).
- Видит товар, оставляет заявку.
- Получает звонок от менеджера.

### 2. 🎬 Streamer (Стример)
- Регистрируется на сайте сам.
- Получает уникальный `refCode` (например `alex_2024`).
- Видит личный кабинет со своей статистикой.
- **Не видит** данные других стримеров.
- **Не видит** контакты клиентов в открытом виде (телефоны частично скрыты — антифрод).

### 3. 🛡 Admin (Администратор / владелец бизнеса)
- Создаётся вручную (через консоль Supabase или promotion-скриптом).
- Видит **всё**: всех стримеров, всех клиентов, все заказы, всю выручку.
- Может одобрять/блокировать стримеров.
- Может менять статус заказа (новый → подтверждён → отправлен → выполнен / отменён).
- Экспортирует данные в Excel/CSV.

## 🛣 Сценарии использования

### Сценарий A — Клиент делает заказ

```
1. Стример Alex в TikTok-стриме говорит: "Переходите по ссылке в био!"
2. Клиент Маша кликает по ссылке: site.com/?ref=alex_2024
3. Браузер запоминает ref в localStorage + cookie на 30 дней.
4. Маша заполняет форму (имя, телефон, кол-во).
5. Сервер находит стримера alex_2024 → привязывает заказ к нему.
6. Админ получает Telegram-уведомление: "Новый заказ от Alex".
7. Менеджер перезванивает Маше.
```

### Сценарий B — Стример проверяет свою статистику

```
1. Alex заходит на site.com/streamer/login.
2. Логинится email + пароль.
3. Видит:
   - Свою реф-ссылку с кнопкой "Скопировать" и QR-кодом.
   - Цифры за сегодня / неделю / месяц: заказов, выручка, заработок.
   - График заказов по дням.
   - Список своих заказов (имя клиента, телефон скрыт, сумма, статус).
```

### Сценарий C — Админ управляет платформой

```
1. Admin заходит на site.com/admin/login.
2. Видит дашборд: суммарные цифры по всему бизнесу.
3. Открывает раздел "Стримеры":
   - Видит топ по выручке.
   - Может заблокировать неактивного стримера.
   - Может вручную создать стримера.
4. Открывает "Заказы":
   - Фильтрует по дате, стримеру, статусу.
   - Меняет статус (подтверждён → отправлен).
   - Экспортирует в Excel.
5. Открывает "Выплаты":
   - Видит, сколько должен каждому стримеру за период.
   - Помечает выплаты как "оплачено".
```

### Сценарий D — Регистрация нового стримера

```
1. Админ выдаёт стримеру пригласительный код (опционально) или ссылку на регистрацию.
2. Стример заходит на site.com/streamer/register.
3. Заполняет: имя, ник в TikTok, email, пароль, желаемый refCode (если занят — система предложит).
4. Подтверждает email (письмо от Supabase).
5. По умолчанию аккаунт = "На модерации".
6. Админ видит заявку, одобряет → стример получает доступ к кабинету.
```

## 🚪 Карта URL-адресов

| URL | Доступ | Что |
|---|---|---|
| `/` | публично | Лендинг + форма заказа |
| `/streamer/register` | публично | Регистрация стримера |
| `/streamer/login` | публично | Вход стримера |
| `/streamer` | streamer | Кабинет стримера |
| `/streamer/orders` | streamer | Список своих заказов |
| `/streamer/profile` | streamer | Профиль, смена пароля |
| `/admin/login` | публично | Вход админа |
| `/admin` | admin | Дашборд админа |
| `/admin/streamers` | admin | Все стримеры |
| `/admin/orders` | admin | Все заказы |
| `/admin/payouts` | admin | Выплаты (roadmap) |
