# 15 · Roadmap

Что НЕ делаем в MVP, но архитектура к этому готова.

## 🥇 Phase 1 — MVP (стартовая версия)

✅ То, что входит в первый релиз:
- Лендинг + форма заказа
- Регистрация / вход стримера
- Личный кабинет стримера
- Админ-панель (стримеры, заказы, экспорт)
- Telegram уведомления
- Тёмная/светлая тема
- Мобильная адаптивность

## 🥈 Phase 2 — Стабилизация и UX (1–2 месяца после MVP)

- [ ] **QR-код реф-ссылки** в кабинете стримера (`qrcode.react`).
- [ ] **Мини-страница «Аккаунт на модерации»** для pending-стримеров.
- [ ] **Уведомления стримеру в Telegram** о его новых заказах (опт-ин в профиле).
- [ ] **Расширенная статистика** в кабинете стримера: воронка, среднее время до подтверждения.
- [ ] **TanStack Table** для всех больших таблиц (сортировка, пагинация, virtual scroll).
- [ ] **Маскировка телефонов** для стримеров (через view).
- [ ] **Анти-фрод** базовый: пометка заказов с одинаковым телефоном/IP за одним стримером.
- [ ] **Honeypot + reCAPTCHA v3** на форме заказа и регистрации.
- [ ] **Sentry** для трекинга ошибок.
- [ ] **Plausible / Umami** для product-аналитики.

## 🥉 Phase 3 — Бизнес-фичи (3–6 месяцев)

- [ ] **Каталог товаров** — таблица `products`, выбор товара в заказе, разные лендинги.
- [ ] **Страница товара** с фото, описанием, отзывами.
- [ ] **Корзина** (мульти-товарный заказ).
- [ ] **Выплаты стримерам** (`/admin/payouts`):
  - Авто-расчёт за период.
  - Статусы (pending / paid).
  - PDF-инвойс.
  - Интеграция с банком / Stripe Connect / крипто-кошельками.
- [ ] **Дифференцированная комиссия**: разный % за разные товары.
- [ ] **Multi-touch attribution** (first/last/linear) с переключателем в настройках.
- [ ] **UTM-метки** в заказах + отчёт по кампаниям.
- [ ] **TikTok Pixel / Conversion API** — отправка событий в TikTok Ads для оптимизации.
- [ ] **Realtime дашборд** (Supabase Realtime подписки).
- [ ] **CRM-функции**: история звонков, заметки менеджера, статусы клиентов.
- [ ] **Интеграция с телефонией** (Mango / Sipuni) — авто-логирование звонков к клиенту.

## 🚀 Phase 4 — Масштабирование (6–12 месяцев)

- [ ] **Мультиязычность** (RU / EN / UZ / KZ): `next-intl`.
- [ ] **Мультивалютность**.
- [ ] **A/B тестирование лендингов** через GrowthBook / Vercel Edge Config.
- [ ] **Конструктор лендингов** для админа (drag-n-drop) — для запуска новых акций без разработчика.
- [ ] **PWA** — стример ставит «приложение» на телефон.
- [ ] **Native mobile app** для стримеров (React Native + та же Supabase).
- [ ] **OAuth-логин** через Google / TikTok.
- [ ] **2FA** для админов (TOTP).
- [ ] **Аудит-лог** действий админа (`audit_log` table).
- [ ] **Многомагазинность** (multi-tenant): один инстанс — несколько брендов.

## 🔬 Phase 5 — Аналитика и AI (1+ год)

- [ ] **Прогноз выручки** на основе истории (простая ML-модель).
- [ ] **Кластеризация стримеров** — кто похож на топов, кому стоит дать больше эфирного времени.
- [ ] **AI-копирайтер** для текстов лендинга (OpenAI API).
- [ ] **Голосовой бот** для предварительной квалификации заявок.
- [ ] **Авто-распределение лидов** между менеджерами.

## 🛠 Технический долг и оптимизация

В фоне на каждой фазе:
- Покрытие тестами (Vitest + Playwright) → 60% → 80%.
- ESLint strict → no implicit any, no unchecked promises.
- Lighthouse Performance ≥ 95.
- DB query monitoring (медленные запросы → индексы / денормализация / materialized views).
- Web Vitals в проде (Core Web Vitals).

## 📦 Возможные «отвязки»

Если когда-то решим уйти от Supabase:
- БД мигрируется в любой Postgres (стандартный SQL).
- Auth → перенести на Lucia / Auth.js / собственный JWT.
- Storage → S3-совместимое (Backblaze, R2).
- Realtime → Pusher / Soketi.

Архитектурно ничто не блокирует переезд за 1–2 недели работы.

## 🎯 Принципы roadmap

1. **Сначала value, потом полировка.** Каждая фаза должна давать измеримую пользу бизнесу.
2. **Не строим то, что не нужно сейчас.** Платформа уже готова к расширению — добавлять можно по факту запроса.
3. **Фичи защищены feature-флагами.** Раскатываем постепенно.
4. **Тесты пишем для критичных сценариев** (создание заказа, логин, выплата). Остальное — по мере надобности.
